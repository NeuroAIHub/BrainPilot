# PaperOrchestra prompt provenance

Source: https://github.com/google-research/paper-orchestra/tree/ca1b3fa01c2970fc7cda32d16245db38d57b3f56

The files in `upstream/` are source snapshots fetched from this fixed commit, including the full Apache-2.0 license. They are audit material, not a Python runtime dependency. `upstream-prompts.json` contains Python AST string-literal values and ordered pieces of the embedded formatted prompts; no upstream module was imported or executed during extraction. That runtime JSON asset also carries the complete upstream license and copyright so they accompany compiled distribution.

`paper-writing.ts` renders those full prompts. Outline and literature prompts use the upstream Python `.format()` brace behavior. Section-writing and content-refinement prompts retain their upstream literal braces. The default AgentReview persona selects the upstream knowledgeable/responsible/benign branches and the complete rating rubric. The active formatting prompts come from `ContentRefinementAgent`, not the unused standalone `format_agent.py` prompt.

Necessary adaptations:

- All calls use the host's current Pi model and `submit_result`; for the response envelope itself, only the shift from free text/code fences to structured tool arguments changes, and the further adaptations below are listed separately. The refinement stage replaces its original two-code-block output section and the matching final user-prompt directive with the exact `submit_result({result: {worklog, latex}})` envelope. Its substantive instructions, source manuscript, reviews, full-source requirement, data constraints and anonymity text remain intact; the unchanged original format is retained in the pinned audit snapshot.
- A `### SINGLE-PASS COMPLETION` section is appended to the runtime refinement system prompt, after the existing adaptations. It scopes the stage to one revision pass, states that reviewer statements are feedback rather than additional evidence, forbids adopting disputed assumptions or inventing data, units, test identities, citations or experiments, requires unresolved reviewer requests and their reasons to be recorded in `worklog.actions_taken`, and asks for the complete revised LaTeX to be submitted after that pass instead of being rewritten repeatedly to chase a higher score. Host-side compilation and subsequent review are unchanged, and no acceptance check is weakened. Upstream source materials, review inputs, template variables and the pinned snapshots are untouched; this is a host scoping adaptation and is one more reason not to claim an exact experimental reproduction.
- The current Pi host does not expose per-stage sampling temperature. Upstream discovery uses 0.1 (targeted) or 0.4 (exploration), section writing uses 0.7, and AgentReview/meta-review use 0.75; this port currently uses the host's model sampling defaults. This difference does not justify claiming an exact experimental reproduction.
- Gemini Google Search grounding is replaced by BrainPilot's enabled paper-library and Tavily tools. Targeted/exploration candidate selection uses retrieved library records and web-result title/content. Complete library metadata can support a citation directly; web candidates require extraction of observed URLs and a separate source-reading stage. Source URLs, quoted title/author/year/abstract/date evidence, retrieval time and metadata hashes are retained. Missing metadata and uncertain cutoff dates are reported rather than fabricated. The earlier Semantic Scholar transport remains covered as historical code, but the active writing workflow does not call it.
- The single sentence `Never explicitly state a limitation.` is removed from the runtime refinement prompt. The original remains visible in the audit snapshot. Missing experiments are not fabricated; this matches the upstream experimental-log constraints.
- PDF bytes are represented through rendered page images and extracted text because the host's model interface is image/text based. Actual compilation and rendering remain required.
- Rendered pages are passed individually at host-controlled resolution rather than assembled into Python/PyMuPDF 2x2 page grids. The same page content is inspected; this is a representation/runtime change.
- Native TypeScript controls orchestration, retries and acceptance. File outputs use host-owned immutable paths; original user inputs are not deleted.
- This implementation restores the upstream default PlotOff path. Optional PaperBanana figure generation is not represented as implemented.
- Bibliographic strings are escaped for valid BibTeX. Generated citation keys remain governed by the original prompts and downstream review/refinement; no new regex-based manuscript citation gate is inserted. Candidate titles must occur in retrieved evidence. Accepted records require matching titles, source-supported authors and abstracts, and a publication date demonstrably before the cutoff; same-year records with only a year are not assigned an invented month or day. A local record may legitimately lack a public URL. Empty verified maps and source-tool errors are reported explicitly.
- Discovery uses at most three concurrent tasks and reuses successful retrieval within a run; source resolution is limited to three observed URLs. The upstream Python snapshots and their original search behavior remain unchanged for audit.
- The formatting-fix stage is scoped to formatting. Its runtime prompt asks for citation keys, bibliography resources, mechanism and metadata to be preserved, forbids adding or removing references and converting an external bibliography to inline entries or the reverse, and leaves content-only requests unresolved. Before the candidate is compiled, the host compares the previous source with the candidate and rejects one whose references changed: the candidate is still saved for audit, the `-format-1` compile is skipped, the reviewed manuscript and its PDF are retained, and the format worklog records `REJECTED_REFERENCE_CHANGE` with reason codes alongside the run issue. The check is a syntactic preservation comparison only — it does not verify that any citation is correct, real or supported, and an unverified key already present in the reviewed manuscript stays present. It applies to this one formatting adoption point; the baseline and content-refinement stages keep their original prompts and acceptance rules with no citation gate inserted before them.

- Review failures are stored as errors without fabricated numeric grades. A completed reviewer ensemble is saved before meta review; an incomplete refinement review is recorded as `REVIEW_INCOMPLETE`, preserving the last valid manuscript and review.
- The formatting preservation check also rejects syntax it cannot inspect confidently. This preserves the previous source and PDF without asserting that references necessarily changed.

No sentence-level revision set, author-approval stage, or personal manuscript-editing policy is part of this workflow.
