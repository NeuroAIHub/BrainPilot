## Clone and Build

```bash
git clone https://github.com/NeuroAIHub/BrainPilot.git
cd BrainPilot
npm install
npm run build
```

## Run From Source

```bash
npm run bp -- up
```

For a no-key local run:

```bash
BP_MOCK=1 npm run bp -- up
```

With `npm run`, keep the `--` separator so CLI flags are forwarded correctly.

## Common Checks

Run these before opening a PR:

```bash
npm run typecheck
BP_MOCK=1 npm test
npm test -w @brainpilot/web
npm run build -w @brainpilot/web
```

Build the docs:

```bash
npm run docs:build
npm run docs:check
```

## Package Layout

| Package | Role |
| --- | --- |
| `@brainpilot/protocol` | Shared wire and domain schemas |
| `@brainpilot/runtime` | Agent orchestration, session state, MCP bridge, runtime server |
| `@brainpilot/backend-core` | REST and SSE backend core |
| `@brainpilot/web` | Browser UI |
| `@brainpilot/app` | npm CLI package: `brainpilot` / `bnpt` |
| `@brainpilot/skills` | Built-in skills content library |
| `@brainpilot/client-cli` | Headless verification client |
| `@brainpilot/docs` | Static public docs site |

## Documentation Workflow

Docs live in:

```text
packages/docs/content/docs/
```

English pages use `page-name.mdx`. Simplified Chinese pages use `page-name.zh-cn.mdx`.

Do not put real provider keys, MCP tokens, or internal-only endpoints in public docs. The docs CI includes a basic secret scan, but reviewers should still check examples manually.

## Pull Requests

Documentation-only changes can be opened directly as PRs. New features or architecture changes should start with an issue or discussion before implementation.

## Dataset checks and documentation parity

```bash
BP_MOCK=1 npm test -- packages/backend-core/test/datasets.test.ts packages/backend-core/test/datasetJobs.test.ts
npm test -w @brainpilot/web -- src/__tests__/datasetMarketplace.test.ts src/__tests__/datasetFeedback.test.ts
```

The backend suite includes local HTTP recovery fixtures and does not need a large public-data transfer. The separate `npm run test:datasets` command downloads public files; review its script and disk/network budget before running it.

Keep the English and Chinese pages and both `meta*.json` navigation files aligned. Cloud vendors the documentation content at an exact upstream commit and renders it in its own SPA; a successful standalone docs build does not prove that the hosted copy is current. A release should verify both builds and the hosted routes.
