## When to Use Docker

The npm installation is the simplest single-user setup. Use Docker when you need a reproducible
runtime, stronger process isolation, GPU dependencies, or one sandbox per hosted user.

| Mode | Main process | Sandbox | Best for |
| --- | --- | --- | --- |
| npm | Local | Local process | One trusted user |
| Static Compose | Container | One fixed container | Self-hosted single-user deployment |
| Dynamic / hosted | Shared container | One container per user | A service behind an authentication gateway |

The official `sandbox` images contain the BrainPilot runtime and scientific environment. They are
not a standalone web application; a BrainPilot main process or the hosted cloud layer connects to
them over the runtime API.

## Official Sandbox Images

Use a fixed release tag in production. `latest` follows the newest release and is convenient for
testing, but it can change on the next publication. The current images target `linux/amd64`.

| Variant | Global (GHCR) | Mainland China (Alibaba Cloud ACR) |
| --- | --- | --- |
| CPU | `ghcr.io/neuroaihub/brainpilot-sandbox:0.1.2` | `brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox:0.1.2` |
| GPU | `ghcr.io/neuroaihub/brainpilot-sandbox-gpu:0.1.2` | `brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox-gpu:0.1.2` |

Both endpoints allow anonymous pulls. Mainland China users should prefer ACR; other users should
prefer GHCR.

```bash title="Global"
docker pull ghcr.io/neuroaihub/brainpilot-sandbox:0.1.2
docker pull ghcr.io/neuroaihub/brainpilot-sandbox-gpu:0.1.2
```

```bash title="Mainland China"
docker pull brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox:0.1.2
docker pull brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox-gpu:0.1.2
```

The CPU image includes Node.js, Python, pip, curl, and the BrainPilot runtime. The GPU image adds
CUDA 12.4, PyTorch 2.6.0, and the published scientific GPU base environment.

## Static Single-User Deployment

Clone the repository and create the local environment file:

```bash
git clone https://github.com/NeuroAIHub/BrainPilot.git
cd BrainPilot
cp .env.example .env
```

Set a provider key in `.env`, or set `BP_MOCK=1` for a no-key smoke test. Build and start the
default CPU deployment:

```bash
docker compose up -d --build
docker compose ps
```

Open `http://localhost:9001`. Runtime data is persisted under `BP_DATA_DIR` (default:
`./brainpilot`). Stop the deployment with `docker compose down`; this does not delete the data
directory.

### Use the Prebuilt CPU Sandbox

To avoid rebuilding the CPU sandbox, set its full registry path and pull it first. Build only the
main image, then start Compose without rebuilding the sandbox:

```bash
export BP_SANDBOX_IMAGE=brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox:0.1.2
docker compose pull sandbox
docker compose build main
docker compose up -d --no-build
```

Replace the ACR path with the GHCR path when outside mainland China.

## GPU Deployment

GPU mode requires all of the following on the host:

1. An NVIDIA GPU and a working driver (`nvidia-smi` succeeds).
2. Docker Engine.
3. NVIDIA Container Toolkit configured for Docker.

Confirm that Docker can expose the GPU before starting BrainPilot:

```bash
docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
```

For a source build, use the GPU override. It selects the `gpu` Dockerfile stage:

```bash
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d --build
```

To use the official prebuilt GPU sandbox instead:

```bash
export BP_SANDBOX_IMAGE_GPU=brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox-gpu:0.1.2
docker compose -f docker-compose.yml -f docker-compose.gpu.yml pull sandbox
docker compose build main
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d --no-build
```

Verify PyTorch can see the GPU:

```bash
docker run --rm --gpus all --entrypoint python \
  brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox-gpu:0.1.2 \
  -c 'import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))'
```

## Dynamic and Hosted Deployment

Dynamic mode runs one sandbox per user through the host Docker daemon. Build the shared main
service and point it at a versioned sandbox image:

```bash
export BP_SANDBOX_IMAGE=brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox:0.1.2
docker pull "$BP_SANDBOX_IMAGE"
docker compose -f docker-compose.dynamic.yml up -d --build
```

The hosted BrainPilot cloud layer supports separate CPU and GPU images:

```dotenv
BP_SANDBOX_IMAGE_CPU=brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox:0.1.2
BP_SANDBOX_IMAGE_GPU=brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox-gpu:0.1.2
```

After changing either value, pull the new image and use the cloud deployment procedure to roll
out the new target. Existing user containers may continue on their old image until they are
reclaimed or rebuilt, depending on the host orchestrator policy.

## Security Boundary

Docker provides useful process and filesystem isolation, but a default Docker container is not a
hard multi-tenant security boundary.

- Treat access to `/var/run/docker.sock` as root-equivalent host access.
- Put an authentication gateway in front of dynamic mode. The gateway must overwrite, rather
  than trust, the client-supplied `X-BP-User` header.
- Give each user a separate host data directory and avoid mounting unrelated host paths.
- Run untrusted workloads on dedicated hosts and add stronger isolation such as gVisor, Kata, or
  microVMs when the threat model requires it. GPU compatibility should be evaluated separately.
- Pin production deployments to a version tag or image digest and upgrade deliberately.

## Updating Images

Pull a new fixed tag, update the corresponding environment variable, and recreate the affected
containers:

```bash
docker pull brainpilot-registry.cn-wulanchabu.cr.aliyuncs.com/brainpilot/sandbox:0.1.2
docker compose up -d --no-build --force-recreate sandbox
```

Do not use `docker compose down -v` unless you intentionally want to remove Compose-managed
volumes.

## Troubleshooting

- **`manifest unknown`** — verify the repository path and version tag.
- **`denied` or `unauthorized`** — confirm you copied the public endpoint shown above; the ACR
  `-vpc` endpoint is only for machines attached to the configured Alibaba Cloud VPC.
- **GPU not detected** — run the standalone CUDA `nvidia-smi` check first, then verify
  `nvidia-container-toolkit` and Docker runtime configuration.
- **Main cannot reach sandbox** — check `docker compose ps`, then inspect `docker compose logs
  sandbox` and confirm the runtime health check reaches port 8081.
- **Pulls are slow in mainland China** — use the ACR endpoint instead of GHCR.
