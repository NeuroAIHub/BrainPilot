---
title: 快速上手
description: 安装 BrainPilot、连接模型服务商、运行首个任务并检查结果。
---

BrainPilot 是一个面向脑科学研究的开源、人在回路智能体工作台。它运行在你的电脑或服务器上，通过浏览器使用，可以协调专业智能体、领域技能、模型服务商、文件和外部工具。

本指南会带你从全新安装走到一个小型、可复核的任务。如果 Node.js 和模型服务商 key 已经准备好，整个过程大约需要五分钟。

> **开始之前：**不要上传可识别的受试者数据、原始临床记录、密码、API key 或其他机密材料。请先对研究数据进行去标识化，并遵守所在机构的伦理审批、知情同意和数据管理要求。

## 1. 检查环境要求

你需要：

- **Node.js 22 或更高版本**
- **npm**，随 Node.js 一起安装
- 一个模型服务商 API key；也可以先使用无 key 的 mock 模式

检查 Node.js 版本：

```bash
node -v
```

如果结果低于 `v22`，请先安装更新的 Node.js 版本。

## 2. 安装并启动 BrainPilot

全局安装已经发布的 npm 包，然后启动：

```bash
npm install -g @brainpilot/app
brainpilot up
```

在浏览器中打开终端打印的本地地址。进程默认在前台运行；按 `Ctrl-C` 可以停止。`bnpt` 是同一个命令的短别名。

如果想在添加真实 key 之前验证安装，可以使用 mock 模式：

```bash
BP_MOCK=1 brainpilot up
```

Mock 模式只用于产品冒烟测试，不能为真实研究任务提供模型能力。

## 3. 配置并测试模型服务商

打开 **Settings → Providers（服务商）→ Add Provider（添加服务商）**，根据服务商官方文档填写：

| 字段 | 应填写的内容 |
| --- | --- |
| Provider name | 便于自己识别连接的本地名称 |
| Base URL | 服务商 API 根地址 |
| Protocol | 该端点实际提供的请求格式 |
| API key | 服务商签发的秘密凭证 |
| Models | 服务商接受的准确模型或 deployment ID |

应根据端点行为选择协议，不要根据模型名称猜测：

| 端点行为 | BrainPilot 协议 |
| --- | --- |
| 兼容 Anthropic `/messages` | `Anthropic Messages` |
| 兼容 OpenAI chat/completions | `OpenAI Completions` |
| OpenAI Responses API | `OpenAI Responses` |
| Azure 托管的 Responses API | `Azure OpenAI Responses` |

保存后：

1. 点击 **Use（使用）**，将该服务商设为新会话的默认服务商。
2. 点击 **Test（测试）**，通过所选协议和第一个已配置模型发送一次最小真实请求。
3. 确认服务商返回健康结果。测试可能消耗少量服务商额度。

![在 BrainPilot 中添加并测试模型服务商](/images/guide/provider-setup.gif)

动画使用的是特意设置的虚假地址和 key。不要把秘密信息复制到 Prompt、截图、反馈消息或代码仓库中。CLI 配置、协议细节和配置文件位置请参阅[模型服务商](https://brainpilot.chat/docs/zh-cn/providers)。

## 4. 运行一个小型首个任务

先使用成本较低、结果容易核验的请求：

1. 点击 **New chat（新建会话）**。
2. 确认消息框旁边显示的模型。
3. 写清目标、期望输出，以及需要人工批准的步骤。
4. 发送请求，并在会话启动时保持页面打开。

可以尝试这个例子：

> 为 fMRI 分析方案制作一份简短的复核清单。指出每项需要人工确认的假设。不要实际执行分析，也不要虚构缺失的研究信息。

![创建第一个 BrainPilot 任务](/images/guide/first-task.gif)

在真实任务中，一个有效请求通常包含五部分：

1. **目标**——需要做出的决定、分析或产物。
2. **数据与背景**——格式、规模、研究背景和已知局限。
3. **方法约束**——必须使用或禁止使用的方法、参数和验证规则。
4. **交付物**——代码、图、表格、报告、日志或机器可读结果。
5. **复核节点**——智能体必须解释或暂停等待批准的选择。

## 5. 检查工作过程，而不只看最终答案

BrainPilot 让工作过程可以检查，但不保证科学结论正确。在依赖结果之前，请检查：

- **Chat（对话）**——请求、澄清、中间决策和最终回复。
- **Files（文件）**——上传的输入、生成的代码、图、表格、报告和日志。
- **Agents（智能体）**——参与了哪些专业角色，以及它们的职责有何区别。
- **Trace（轨迹）**——重要步骤、工具调用、输出和产物。

对于研究任务，至少核验：

- 实际使用的输入文件、shape、单位、排除规则和缺失值；
- 每个重要数值背后的代码和保存产物；
- 统计假设与训练/测试划分；
- 引用与原始来源是否一致；
- 哪些结论仍需要人工判断或独立复现。

公开的[演示案例](https://brainpilot.chat/demos)提供了已经完成的运行记录，无需上传自己的数据即可检查。

![检查一次完整运行及其 Trace](/images/guide/inspect-trace.gif)

## 6. 确认首次运行健康

满足以下条件后，再开始更大的任务：

- 服务商已经保存、启用并通过 **Test（测试）**；
- 新会话显示预期的服务商和模型；
- 任务完成时没有服务商、鉴权或运行环境错误；
- 可以从会话列表重新打开该任务；
- 可以检查它的 Trace 和生成文件。

确认这些项目后，再使用更大的文件、更长的任务或费用更高的模型。

## 首次运行常见问题

| 现象 | 优先检查 |
| --- | --- |
| `brainpilot: command not found` | 确认 npm 全局安装和 npm 二进制目录 |
| Node.js 版本错误 | 安装 Node.js 22 或更高版本 |
| 端口被占用 | 运行 `brainpilot up --port 9010` |
| 服务商返回 401/403 | 重新检查 key 以及账户/模型权限 |
| 服务商返回 404 | 对照官方文档检查 Base URL、协议和 Model ID |
| 服务商返回 429/额度错误 | 等待、减少调用或补充服务商额度 |
| 修改服务商后当前会话没有变化 | 点击 **Use（使用）** 后新建会话 |
| MCP 工具没有出现 | 检查传输方式和鉴权，然后新建会话 |

详细命令和诊断方法请参阅[故障排查](https://brainpilot.chat/docs/zh-cn/troubleshooting)。如果 mock 模式正常但真实请求失败，应重点检查服务商或外部工具配置，而不是反复重装 BrainPilot。
